# Production use and support

This reference describes the project's published API and documented commitments so teams can evaluate their own deployment requirements.

| Subject                                 | Current scope and evidence                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Angular/package compatibility           | The current 22.x package line requires Angular 22; see the [package peer ranges](../projects/angularx-qrcode/package.json). The [historical version mapping](../README.md#compatibility-and-maintenance) identifies older package lines for earlier Angular majors. Compatibility is separate from ongoing maintenance.                                                                                                                |
| Active maintenance                      | Normal fixes focus on 22.x. Older lines receive best-effort attention, with no guaranteed fixes or security backports. See [compatibility and maintenance](../README.md#compatibility-and-maintenance).                                                                                                                                                                                                                                |
| Vulnerability reporting                 | Use the private maintainer contact and reporting instructions in [SECURITY.md](../SECURITY.md). There is no guaranteed acknowledgement or resolution deadline.                                                                                                                                                                                                                                                                         |
| Runtime dependencies                    | The published package directly depends on `qrcode` and `tslib`; Angular common/core are peers. Repository development tools are separate, and direct dependencies are not the complete transitive graph. See [runtime dependency scope](../README.md#runtime-dependencies).                                                                                                                                                            |
| Release integrity and supply chain      | Pinned Actions, script-disabled installs, release-age settings, test/build gates, and read-only checks are documented in [supply-chain hardening](security/npm-supply-chain-hardening.md) and [cache isolation](security/github-actions-cache-poisoning.md). These are repository controls, not runtime vulnerability fixes or guarantees. External environment protection and trusted-publisher settings must be verified separately. |
| Provenance verification                 | Follow [the version-specific verification procedure](security/npm-supply-chain-hardening.md#verify-a-releases-provenance). The documented verification is for 22.0.1; inspect the exact version you consume. Provenance identifies reported source/build/publisher information and does not prove code safety.                                                                                                                         |
| Local generation and external resources | Payload generation is local, with no required hosted QR-generation service or demo. External canvas logos can trigger requests. See [local generation, privacy, and offline use](../README.md#local-generation-external-resources-and-privacy).                                                                                                                                                                                        |
| SSR/runtime constraints                 | Real Angular server rendering is validated by `npm run test:ssr`: all renderers leave an empty QR placeholder, defer validation, and emit no events. QR visuals, logos, and downloads require browser execution. Hydration is untested. See [SSR scope](../README.md#ssr---server-side-rendering).                                                                                                                                     |
| Production QR use                       | Review [density, quiet zones, correction levels, logos, SVG, Unicode, and real-device testing](../README.md#production-qr-guidance). Scanability depends on content, presentation, and scanning environment. Use [the typed error output](../README.md#handling-generation-errors) for current-render failures.                                                                                                                        |
| Available support                       | Report ordinary bugs and request help through [GitHub issues](https://github.com/Cordobo/angularx-qrcode/issues), with a minimal reproduction. Contributions are welcome; maintainer responses depend on availability. Use the private security channel for vulnerabilities. The project does not document a paid support offering or contractual support entitlement.                                                                 |
| SLA                                     | There is no published response or resolution SLA; see the [security and support expectations](../SECURITY.md#versions-and-security-fixes).                                                                                                                                                                                                                                                                                             |
| LTS                                     | There is no formal LTS commitment or guaranteed support period. Project history and historical compatibility do not change that policy.                                                                                                                                                                                                                                                                                                |

Maintainers use [curated release notes](releases/README.md) to separate user-visible behavior, compatibility/migration, consumer security, repository hardening, and tooling changes. Consumers should review each release's upgrade guidance and validate their own application before deployment.
